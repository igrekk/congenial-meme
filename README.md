# Рабочее время

Предварительная рабочая версия 0.1.0 от 20 ноября 2026 года.

Личное локальное приложение для учета часов по проектам **INAL, INAC, GCVU, ECGP**. Данные хранятся на этом компьютере. Интернет и облачный аккаунт для учета времени не нужны.

## Запуск на Windows

1. Откройте папку проекта.
2. Дважды нажмите **`Start-WorkTime.cmd`**.
3. В браузере откроется приложение. Окно запуска оставьте открытым.

Нужен Python **3.10 или новее** с модулем SQLite (он входит в стандартный установщик Python). Скрипт также умеет находить Python, установленный вместе с Codex. Загрузка дополнительных пакетов не требуется.

Другой способ запуска:

```powershell
python server.py --open-browser
```

Обычный адрес — `http://127.0.0.1:8765`. Если порт занят другой программой, приложение выбирает ближайший свободный. Точный адрес показан в окне запуска. Доступ открыт только с текущего компьютера.

Чтобы остановить сервер, нажмите Ctrl+C в окне запуска или закройте окно. Повторный запуск открывает сохраненные данные.

## Что уже работает

- Четыре проекта и задачи внутри проектов.
- Ручная запись: дата, задача, длительность, примечание. Поддерживаются `2,5`, `2.5`, `02:30`, `00:00:30`.
- Календарь месяца: в ячейке дня — объекты и сумма часов по каждому; по нажатию — задачи, записи и подробности дня.
- Переход между месяцами, фильтр проекта и итоги выбранного месяца.
- Исправление записи, удаление и отмена удаления.
- Создание, переименование и архивирование задач с сохранением истории.
- Один таймер, пауза и продолжение, автоматическая запись после завершения.
- Восстановление таймера после закрытия браузера и перезапуска сервера.
- Разделение времени таймера на календарные даты по московскому времени.
- Создание, скачивание и восстановление резервных копий в разделе «Данные».

Новые рабочие базы пустые: демонстрационные записи из макета в них не переносятся.

## Календарь

Главный экран показывает месяц с понедельника по воскресенье. Каждая заполненная ячейка содержит краткие строки, например `INAL — 3,5 ч` и `ECGP — 0,75 ч`. Время нескольких задач одного объекта за день суммируется.

Нажмите день, чтобы открыть подробный список задач, примечаний и записей времени. Из этого окна можно изменить запись, продолжить задачу с таймером или добавить время за выбранную дату. Кнопка «Внести время» над календарем раскрывает форму ручного ввода и таймер.

Объекты в этой версии — проекты INAL, INAC, GCVU и ECGP. Часы в ячейках показаны десятичным числом; подробности содержат точные часы, минуты и секунды. Итог за месяц исключает видимые соседние даты предыдущего и следующего месяца.

## Правила таймера

**Закрытие браузера, остановка сервера и сон компьютера не останавливают запущенный таймер.** При открытии время восстанавливается по сохраненному началу. Нажмите «Пауза», если не работаете. После завершения длительность записи можно исправить вручную.

Одновременно разрешен один незавершенный таймер, включая таймер на паузе. Переключение между задачами требует завершения текущей сессии. Повторная команда завершения не создает дубликатов.

Текущий часовой пояс — **Europe/Moscow**. Ручная запись содержит дату и длительность; ей не приписывается вымышленное время начала.

## Данные и резервные копии

Рабочая база: **`data/tracker.sqlite3`** рядом с `server.py`. Резервные копии находятся в `data/backups/`. Эти каталоги и файлы базы исключены из Git: личные часы не отправляются в репозиторий вместе с кодом.

В разделе «Данные» можно создать копию и скачать ее. Перед восстановлением приложение сохраняет страховочную копию текущей базы. Незавершенный таймер нужно предварительно завершить. Восстановление заменяет текущие записи выбранной копией, а не объединяет базы.

Для отдельного каталога данных:

```powershell
python server.py --data-dir "D:\WorkTimeData" --open-browser
```

Не открывайте один файл базы одновременно с разных компьютеров через сетевую папку. Синхронизация устройств в эту версию не входит.

## Перенос на другой компьютер

1. Завершите или поставьте таймер на паузу и остановите приложение.
2. Скопируйте папку проекта или скачайте исходники из GitHub.
3. Для переноса личных записей отдельно скопируйте каталог `data` в новую папку приложения. Исходники из GitHub не содержат личной базы.
4. На другом компьютере установите Python 3.10+ и запустите `Start-WorkTime.cmd`.

Запущенный таймер после переноса продолжит учитывать время с сохраненного начала; поставленный на паузу останется на паузе. Если нужны независимые базы на разных ПК, не переносите каталог `data`.

Для продолжения разработки передайте Codex папку проекта, этот файл и `development-plan.md`. Если есть `CONTINUE.md`, он содержит последнее состояние и следующие шаги.

## Структура

- `static/` — интерфейс без внешних сетевых зависимостей.
- `backend/` — задачи, записи времени, таймер, сводки и хранение SQLite.
- `server.py` — локальный HTTP API и выдача интерфейса.
- `tests/` — проверки правил учета и HTTP API.
- `development-plan.md` — план развития.

Проверки из папки проекта:

```powershell
python -m unittest discover -s tests -v
```

Проверки календарных дат и сумм (нужен Node.js только для разработки):

```powershell
node --test tests/test_calendar.cjs
```

Результат проверки 20 ноября 2026 года: **22/22 теста сервисов и HTTP и 8/8 проверок календаря прошли**. В браузере с настоящим API также проверены ручной ввод и изменение записи, сохранение после перезагрузки, удаление с отменой, создание задачи, пауза и восстановление таймера, его завершение с записью в календарь и создание резервной копии. Для календаря проверены подробности дня, суммирование нескольких задач одного проекта, фильтры, переход месяца, добавление из пустого дня и отображение четырех проектов при ширине 320 px. Тестовые данные хранятся отдельно от рабочей базы.
